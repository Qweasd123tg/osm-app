# Слои — прототип картографического приложения

Монорепозиторий картографического приложения с необычными слоями. Здесь лежат
Android-прототип, Python-движок расчёта теней, тесты, исходные OSM-кэши и готовые
web-примеры. Первый рабочий слой показывает движение теней от зданий в течение
дня.

## Что уже работает

- мобильная карта на MapLibre;
- локально встроенные здания и 49 кадров теней для района Московской в
  Санкт-Петербурге;
- ползунок времени и автоматическое воспроизведение;
- режимы 2D и 3D;
- светлая и тёмная подложки;
- общий реестр четырёх встроенных слоёв: здания, тени, ветер и направление солнца;
- независимое включение, прозрачность и порядок слоёв, включая здания
  офлайн-города в видимой области;
- окраска зданий по достоверности высоты с легендой в настройках зданий;
- карточка здания по нажатию;
- поиск места, загрузка района из центра карты и примерная геолокация;
- динамическая подмена зданий и кадров теней без перезапуска карты;
- текущий ветер Open-Meteo с направлением движения на карте;
- направление солнца для выбранного времени, скрытое ночью;
- выбор даты и часового пояса для расчёта нового района;
- импорт локального GeoJSON с точками, линиями и полигонами, настройка цвета,
  переход к слою, просмотр свойств объекта и удаление слоя;
- скачиваемый офлайн-пакет Санкт-Петербурга: известный размер, прогресс,
  отмена, повторная загрузка и удаление;
- пространственный индекс SQLite для зданий из GeoPackage: RTree, а при его
  недоступности — bbox-таблица с B-tree, поэтому целиком город не читается;
- при установленном пакете здания текущего viewport подгружаются локальными
  Web Mercator-тайлами z15–z17 при масштабе от 14,25; слишком широкий или
  плотный viewport просит приблизить карту;
- заготовки каталога для следующих слоёв;
- сохранение выбранных настроек и до 20 именованных наборов в `localStorage`.

В панели слоёв можно менять их порядок; в 3D взаимное перекрытие также зависит
от глубины объёмной геометрии. Изменение прозрачности, цвета и видимости не
сбрасывает положение камеры. Набор сохраняет режим 2D/3D, подложку, настройки
слоёв и время в формате `HH:mm`, но не место или дату расчёта. Для импортированных
слоёв сохраняются ссылки на локальные записи и настройки, а сама геометрия
остаётся в библиотеке GeoJSON. Время применяется
при совпадении с кадром текущего района; иначе используется его кадр по
умолчанию. Наборы можно применять и удалять. Если запись в локальное хранилище
не удалась, интерфейс сообщает об этом; текущие настройки продолжают работать.
Панель поддерживает переход по элементам клавишей Tab и закрытие по Escape.

Библиотека GeoJSON хранится в IndexedDB: до 5 файлов, каждый не более 2 МиБ,
суммарно до 8 МиБ. В браузере используется выбор файла, на Android — системный
диалог Storage Access Framework с доступом к явно выбранному файлу. Карточка
объекта показывает простые значения свойств. Поддерживаются встроенные слои и
локальные статические данные; загрузки исполняемых плагинов и внешних временных
рядов пока нет.

Дата и часовой пояс задаются отдельно от наборов слоёв. Текущий снимок ветра не
меняет выбранную дату расчёта солнца. Встроенное демо подписано своей датой —
17 июля 2026 года; оно не представляет текущие тени.

MapLibre и демо-район со всеми кадрами теней лежат внутри APK и остаются
fallback без сети. Для нового района APK сам по HTTPS получает сырые данные
OSM, поиск места и необязательный снимок ветра. Нативный движок на устройстве
разбирает здания и высоты, рассчитывает положение солнца и лениво строит
геометрию тени; посещённые сырые районы сохраняются в кэше.
Сырой кэш ограничен 64 МиБ, сгенерированные сцены — 24 МиБ, отдельный кэш
viewport-тайлов — 96 МиБ; старые файлы удаляются автоматически. При загрузке
интерфейс показывает полученные МиБ, а при обрыве соединения переключается
между независимыми Overpass-провайдерами.

В разделе «Офлайн-города» доступен Санкт-Петербург из
[BBBike](https://download.bbbike.org/osm/bbbike/SanktPetersburg/): архив
GeoPackage имеет известный размер около 96 МБ, после распаковки пакет занимает
около 249 МБ в приватном хранилище приложения. APK скачивает архив только по
явному действию пользователя, проверяет ZIP/контрольную сумму при её наличии и
схему GeoPackage, строит пространственный индекс SQLite (RTree, при
недоступности — bbox-таблицу с B-tree), а затем атомарно заменяет установленный
файл. Пока этот шаг не завершён, пакет не считается установленным. Отмена
прерывает сетевое чтение и оставляет прежний пакет нетронутым; удаление убирает
реальный файл и его метаданные.

Python-движок остаётся эталонным генератором статических 2D/3D-карт и основой
для будущих golden-сравнений, но не является runtime-backend приложения.
Подробнее: [`shade-engine/README.md`](shade-engine/README.md).

## Сборка

Нужны JDK 17 и Android SDK 36. Отдельно устанавливать Gradle не требуется:
репозиторий использует Gradle Wrapper.

```bash
git clone https://github.com/Qweasd123tg/osm-app.git
cd osm-app
./gradlew assembleDebug
```

Готовый APK появится здесь:

```text
app/build/outputs/apk/debug/app-debug.apk
```

Проект также можно открыть в Android Studio и запустить на телефоне обычной
кнопкой Run.

## Районы и офлайн-города на устройстве

После выбора места Android через HTTPS загружает сырой ответ OSM и сохраняет
его в локальном кэше. Нативный `OnDeviceSceneEngine` вне UI-потока нормализует
геометрию зданий и высоты, вычисляет солнце и отдаёт WebView здания и нужный
кадр тени через Android bridge. Геометрия создаётся лениво для выбранного
времени, поэтому приложение не обязано держать в памяти весь дневной набор
кадров нового района.

Если точка находится внутри установленного пакета Санкт-Петербурга, движок
запрашивает через пространственный индекс SQLite (RTree, при недоступности —
bbox-таблица с B-tree) только здания, пересекающие расчётный прямоугольник
сцены: видимые 450 м и запас 350 м для длинных теней. GeoPackage хранит
геометрию и OSM-теги `height`, `building:levels`, `min_height`,
`building:min_level` и `building`; нативный движок на телефоне по-прежнему
нормализует геометрию, выводит высоты, считает солнце и лениво строит тени.
Предрассчитанных теней и сетевого сервера в пакете нет.

Это отдельный от сцены путь: после перемещения карты WebView запрашивает
локальные тайлы зданий видимого viewport. Он не расширяет 450-метровый радиус
расчёта сцены и не пересчитывает тени для всего города.

За пределами покрытия пакета сохраняется текущий порядок: валидный сырой кэш
района, затем точечный Overpass. Интернет всё ещё нужен для нового места,
поиска, подложки и обновления ветра. Без сети доступны встроенный демо-район,
ранее посещённые районы и область установленного пакета; если сетевой слой
ветра недоступен, тени продолжают работать. Приложение не требует отдельного
Python-сервера, адреса API или reverse proxy.

## Ограничение нагрузки

Обычный режим ограничивает плотность рендеринга значением DPR 1,5, экономный —
1; кэш растровой подложки ограничен 64 тайлами. Для зданий видимой области
обычный режим допускает до 64 тайлов, 16 000 объектов и 16 МиБ оценённого объёма
сериализованных данных; экономный — 32 тайла, 6 000 объектов и 8 МиБ. Это лимиты
данных viewport, а не гарантированный предел всей памяти приложения.

Ползунки объединяют изменения в один кадр отрисовки, runtime пропускает
неизменившиеся свойства и порядок слоёв. В фоне приостанавливаются задачи
viewport и расчёт кадров; при выключенных тенях новые кадры не рассчитываются.
Отмена загрузки района и проверки устаревших ответов защищают текущую сцену,
активный расчётный контекст сохраняется при очистке кэша. Влияние этих мер на
FPS, память и батарею реального телефона требует отдельных измерений.

## Устройство проекта

- `app/src/main/java/app/sloi/map/MainActivity.java` — нативная Android-оболочка и bridge WebView;
- `app/src/main/java/app/sloi/map/OnDeviceSceneEngine.java` — загрузка, кэш и расчёт сцены на устройстве;
- `app/src/main/java/app/sloi/map/CityPackStore.java` — загрузка BBBike GeoPackage,
  проверка, атомарная установка и пространственный индекс SQLite офлайн-города;
- `app/src/main/assets/index.html` — разметка интерфейса карты и каталога;
- `app/src/main/assets/app.css` — оформление и адаптивная компоновка;
- `app/src/main/assets/app.js` — взаимодействие интерфейса, карты и Android bridge;
- `app/src/main/assets/layer-settings.js` — реестр встроенных слоёв,
  нормализация настроек и формат локальных наборов;
- `app/src/main/assets/layer-runtime.js` — жизненный цикл слоёв MapLibre,
  применение настроек и проверка импортируемого GeoJSON;
- `app/src/main/assets/layer-library.js` — локальная библиотека GeoJSON в IndexedDB;
- `app/src/main/assets/map-data.js` — встроенная демо-геометрия;
- `app/src/main/assets/vendor/` — локальная сборка MapLibre GL JS;
- `shade-engine/` — Python-эталон расчётов и статический web-экспорт;
- `shade-engine/cache/` — два сохранённых OSM-района для работы без Overpass;
- `shade-engine/examples/` — готовые 2D- и 3D-карты;
- `shade-engine/tests/` — регрессионные тесты Python-эталона геометрии и временной шкалы;
- `tools/build_map_data.py` — обновление данных из результата Shade Map;
- `tools/check_assets.mjs` — быстрая проверка web-части без Android SDK;
- `tools/test_layer_settings.mjs` — проверки нормализации настроек и наборов;
- `tools/test_layer_runtime.mjs` — проверки runtime и валидации GeoJSON;
- `tools/test_layer_library.mjs` — проверки библиотеки и её лимитов;
- `tools/test_browser.py` — сценарии интерфейса в Chromium через Playwright;
- [`ROADMAP.md`](ROADMAP.md) — текущее направление развития.

## Обновление демо-данных

Установи Python-движок и пересобери 3D-пример:

```bash
python -m venv shade-engine/.venv
source shade-engine/.venv/bin/activate
python -m pip install -e shade-engine

shade-map-3d \
  --bbox 59.8458,30.3100,59.8584,30.3358 \
  --time 2026-07-17T15:00:00+03:00 \
  --cache shade-engine/cache/moskovskaya_buildings.json \
  --label "Метро Московская" \
  --output shade-engine/examples/3d.html

python tools/build_map_data.py
node tools/check_assets.mjs
```

`build_map_data.py` извлекает здания и все временные кадры из нового примера и
обновляет данные внутри APK.

## Проверки без Android SDK

```bash
node tools/check_assets.mjs
node tools/test_layer_settings.mjs
node tools/test_layer_runtime.mjs
node tools/test_layer_library.mjs
shade-engine/.venv/bin/python -m unittest discover -s shade-engine/tests -v
```

Для проверки интерфейса в браузере нужны Python-пакет `playwright` и Chromium:

```bash
python3 tools/test_browser.py --chromium /usr/bin/google-chrome
python3 tools/test_features_browser.py --chromium /usr/bin/google-chrome
```

Проверка использует локальные ассеты и блокирует сетевую подложку. Она покрывает
настройки и порядок слоёв, сохранение наборов, камеру, клавиатуру и ошибку
хранилища. Вторая проверка покрывает импорт и восстановление GeoJSON, солнце,
дату/часовой пояс, отмену и ошибки расчёта, устаревшие ответы и режим экономии.
Динамические здания и ответы нативного движка подставляются тестом; Android-загрузку пакета
нужно отдельно проверять на устройстве.

## Ветер

Скорость и метеорологическое направление «откуда» APK загружает по HTTPS из
Open-Meteo, а карта отдельно показывает направление движения «куда». Это
необязательный сетевой слой: его ошибка не отменяет локальный расчёт теней.
Полная экспериментальная Three.js-симуляция уличных потоков пока остаётся
отдельным прототипом и не смешивается с геометрическим расчётом теней.
