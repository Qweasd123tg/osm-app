# Контракт модулей API v1

`app/src/main/assets/module-host.js` управляет доверенными JavaScript-модулями,
поставляемыми вместе с приложением. Модуль регистрирует манифест и фабрику,
получает настройки, создаёт собственные GeoJSON-слои или запрашивает управляемый
сервис вычислений. Установка сторонних
пакетов, подписи и каталог внешнего кода пока не реализованы.

Host ограничивает свой API и ресурсы, но не создаёт песочницу безопасности.
Bundled-код выполняется в общем WebView и технически может обращаться к
глобальным объектам. Для недоверенного исполняемого кода нужен отдельный
механизм изоляции. Здания пока работают через основной `layer-runtime.js`.
Тени включаются расширением через capability `shadows`, а нативный адаптер
и отрисовка остаются в приложении. Солнце и ветер убраны из продуктового интерфейса.

## Манифест и настройки

| Поле | Контракт |
| --- | --- |
| `id` | Уникальный идентификатор: `[a-z][a-z0-9-]{0,47}`. |
| `apiVersion` | Только `1`. |
| `version`, `title` | Непустые строки длиной до 120 символов. |
| `description` | Необязательная строка, ограниченная 1000 символами. |
| `capabilities` | Массив возможностей `geojson` и/или `shadows`. Неизвестные значения отклоняются. |
| `defaults` | Плоский JSON-объект настроек: строки, конечные числа, флаги и `null`. |

При `configure(id, patch)` разрешены только ключи из `defaults` с прежними
типами. Вложенные объекты и массивы настроек не поддерживаются; размер JSON
ограничен 16 КиБ. Смысловые ограничения, например допустимые направления
маршрута, дополнительно проверяет фабрика. Настройки сохраняются отдельно
от наборов старых слоёв, в записи `sloi-modules-state` версии 1.
В APK эта запись и наборы транспорта используют приватные `SharedPreferences`
Android с подтверждённым дисковым commit; браузерный клиент — `localStorage`.
Адаптер `extension-storage.js` переносит прежнюю запись при первом чтении.
Нативный мост разрешает ровно два ограниченных ключа, без доступа к остальным
настройкам приложения. Отказ записи показывается как предупреждение хранилища.

В интерфейсе формы параметров находятся в полноэкранных «Настройки → Расширения».
Редактор именованных наборов транспорта — на отдельной странице
«Настройки → Наборы транспорта»; рабочая панель транспорта только переключает
готовые наборы и просматривает линии метро.
Этот экран отделён от панели карты и имеет собственный переход назад. На рабочей
странице «Слои» остаются название, включение, статус и действия восстановления;
параметры не занимают место рядом с картой. Переход в настройки сам по себе не
включает модуль и не перемещает камеру. Неотправленные черновики сохраняются
при посторонних уведомлениях host.

## Жизненный цикл

Создание host: `new SloiModules.Host({ map, storage, onChange, anchor, services })`.
`map` — карта MapLibre, `storage` — необязательное локальное хранилище,
`onChange` получает список состояний. По умолчанию слои добавляются перед
`selected-location`. Необязательный `services.shadows` — функция приложения
`(options, signal) => cleanup | Promise<cleanup>`; другие ключи сервисов
не принимаются. При отсутствии сервиса модуль теней получает понятную ошибку.

| Метод host | Поведение |
| --- | --- |
| `register(manifest, factory)` | Регистрирует выключенный модуль; фабрика ещё не запускается. |
| `enable(id)` | Запускает фабрику или оставляет модуль на паузе, если host приостановлен. |
| `disable(id)` | Отменяет текущую сессию и удаляет её ресурсы. |
| `configure(id, patch)` | Проверяет настройки и перезапускает включённый модуль. |
| `restore()` | Восстанавливает сохранённые настройки и включённые модули. |
| `refresh(id)` | Пересоздаёт активную сессию без изменения настроек и камеры, например при смене темы. Выключенный или приостановленный модуль не включает. |
| `get(id)`, `list()` | Возвращает снимки настроек, границ данных и состояния. |
| `setSuspended(true/false)` | Останавливает включённые модули или создаёт для них новые сессии. |
| `dispose()` | Закрывает host и очищает ресурсы. |

Состояния: `disabled`, `loading`, `ready`, `paused`, `error`. Ошибка одного
модуля показывается в его карточке и не выключает остальные. Переключение
видимости документа вызывает паузу/возобновление host. При паузе слои удаляются,
а после возвращения фабрика запускается снова с сохранёнными настройками.

Фабрика может быть асинхронной и возвращать функцию очистки либо `undefined`.
При остановке сессии host отменяет `AbortSignal`, снимает зарегистрированные
обработчики и удаляет собственные источники/слои. Поздняя запись в отменённый
контекст получает `AbortError`; поздно вернувшаяся функция очистки тоже вызывается.
Сетевые запросы фабрики должны использовать `ctx.signal`, а собственные таймеры
и внешние подписки — освобождаться функцией очистки.

## Контекст фабрики

| API | Доступ |
| --- | --- |
| `ctx.settings` | Замороженный снимок настроек этой сессии. |
| `ctx.signal` | Сигнал отмены сессии. |
| `ctx.getView()` | Замороженный снимок `{ center: [lon, lat], zoom, bounds }`. |
| `ctx.map.getView()` | Тот же доступ к камере только для чтения; полного MapLibre API в контексте нет. |
| `ctx.setGeoJson(localId, data, options)` | При capability `geojson` создаёт/обновляет принадлежащий модулю источник и ограниченное оформление. Поля `options` перечислены ниже. |
| `ctx.onMove(callback)` | Подписка на завершение перемещения с объединением событий за 120 мс; возвращает функцию отписки. |
| `ctx.reportError(message)` | Переводит текущую сессию в `error`, отменяет работу и очищает её ресурсы; пользователь может включить повтор. |
| `await ctx.useShadows({ opacity })` | При capability `shadows` получает управляемую сессию нативного расчёта. Доступен одному модулю одновременно. |

До 4 GeoJSON-источников на активную сессию, каждый до 2 МиБ входного JSON.
Геометрия проходит общую проверку `layer-runtime.js`. Оформление не даёт модулю
полный доступ к MapLibre:

| Поле `options` | Контракт |
| --- | --- |
| `color` | Цвет `#rrggbb`, по умолчанию `#286b52`. |
| `colorProperty` | Необязательное имя свойства объекта по шаблону `[a-zA-Z_][a-zA-Z0-9_]{0,31}`. Полный шестизначный hex нормализуется в принадлежащее host поле `__moduleColor`; отсутствующий/неверный цвет заменяется `color`. Один цвет используется для геометрии и локальной подписи. |
| `opacity` | Конечное число 0–1, по умолчанию 0,8. |
| `pointMinZoom` | Конечное число 0–24 при создании слоя, по умолчанию 0. |
| `pointLabelMinZoom` | Отдельный порог подписи, от `pointMinZoom` до 24; по умолчанию равен порогу точек. Метро: точки 10, названия 12. Живой транспорт: точки 12, номера 13. |
| `pointRadius` | Конечное число 2–16 CSS-пикселей, по умолчанию 5. |
| `pointLabel` | Необязательное имя свойства объекта для подписи: `[a-zA-Z_][a-zA-Z0-9_]{0,31}`. Менять это поле существующего источника можно только после перезапуска модуля. |
| `pointLabelStyle` | `"badge"` по умолчанию — небольшая плашка; `"text"` — прозрачный фон и текст с ореолом, как у станций метро. Оба варианта рисуются локально. |
| `pointOpacity` | Необязательное имя свойства по тому же шаблону. Значение свойства приводится к числу, ограничивается 0–1 и умножается на общую `opacity`; отсутствующее/нечисловое даёт множитель 1. |
| `pointMarker` | `"circle"` по умолчанию; `"vehicle"` — цветная капля и отдельная вертикальная пиктограмма транспорта, размер около 38 CSS px. При отсутствии canvas/image API остаётся обычная точка. |
| `pointHeading` | Имя числового свойства компасного курса, по умолчанию `heading`. Конечные 0–359,999° задают направление; отсутствующее/неверное значение рисуется кругом. |
| `pointType` | Имя свойства вида транспорта, по умолчанию `vehicleType`: `bus`, `tram`, `trolley`. |

Подписи точек в WebView рисуются хостом в локальные canvas-значки, без загрузки
шрифтов подложки. Текст ограничен 48 символами; максимум 128 уникальных значков
на сессию. Цвет, текст и вариант оформления входят в ключ значка. Оформление
метро обновляется при смене темы без перемещения камеры. Неиспользуемые значки
удаляются при обновлении данных, общая функция
очистки сессии удаляет оставшиеся после слоёв и источников. Превышение бюджета
оставляет точку без подписи. Среда без canvas/image API использует ограниченную
текстовую подпись MapLibre. Модуль не получает прямого управления изображениями.

Остановки маршрута используют `pointMinZoom: 15`; живой транспорт и метро
задают собственные пороги.
Идентификаторы MapLibre изолированы
пространством имён модуля. Эти ограничения не являются пределом всей памяти
или процессорного времени произвольного JavaScript.

## Минимальный модуль

Следующий фрагмент добавляется внутрь `register(host)` в
`app/src/main/assets/modules/bundled.js`. Он показывает центр видимой карты и
обновляется после перемещения:

```javascript
host.register({
  id: "view-center",
  apiVersion: 1,
  version: "1.0.0",
  title: "Центр карты",
  description: "Точка в центре видимой области",
  capabilities: ["geojson"],
  defaults: { opacity: 0.8 },
}, (ctx) => {
  const update = () => ctx.setGeoJson("center", {
    type: "FeatureCollection",
    features: [{
      type: "Feature",
      properties: { name: "Центр карты" },
      geometry: { type: "Point", coordinates: ctx.getView().center },
    }],
  }, { color: "#4b77be", opacity: ctx.settings.opacity });
  update();
  const unsubscribe = ctx.onMove(update);
  return () => unsubscribe();
});
```

Host сам очищает `onMove`; явная функция очистки в примере также допустима.
Чтобы вывести настройки на странице расширений, добавьте описание полей в `controls`
того же файла, например:

```javascript
"view-center": [
  { key: "opacity", label: "Непрозрачность", type: "number",
    min: 0, max: 1, step: 0.1 },
],
```

Фабрику можно вынести в `modules/view-center.js`, загрузить файл из `index.html`
до `modules/bundled.js` и вызвать её регистрацию в общем `register(host)`.
Для нового обычного GeoJSON-модуля специальные ветки в `app.js` не нужны.
Добавьте сценарий фабрики в `tools/test_bundled_modules.mjs` и браузерный
сценарий включения, изменения настроек, восстановления и выключения.

## Встроенные расширения

Расширения регистрируются выключенными. Сохранённое состояние включения
восстанавливается host; старые настройки встроенных слоёв не включают новый
модуль теней. Координатная сетка удалена из поставляемого набора.

`shadows` находится в `modules/native-shadows.js`. Единственная настройка —
непрозрачность 10–75%. Модуль вызывает `ctx.useShadows({ opacity: value / 100 })`;
даты, фиксированного района и прямого доступа к Android bridge в его API нет.
Сервис приложения рассчитывает текущее время и полную видимую область,
обновляя её после остановки карты. Отключённый модуль не запускает расчёты.

`useShadows` принимает только конечную `opacity` 0,1–0,75. Host не допускает
повторной аренды в одной сессии и одновременно работающих владельцев сервиса.
Функция сервиса обязана вернуть cleanup; host вызывает его ровно один раз
при выключении, изменении настроек, паузе, ошибке или уничтожении. Поздно
завершившаяся асинхронная активация тоже очищается. Фабрика модуля не должна
возвращать эту же функцию повторно: cleanup аренды принадлежит host.

`spb-bus` показывает линию маршрута и остановки по данным
[городского портала транспорта Петербурга](https://transport.orgp.spb.ru/).
Настройки: номер автобуса, направление и видимость остановок. Цвет задан
модулем, отдельного выбора цвета в интерфейсе нет. Остановки отображаются
с zoom 15. Используются:

- `POST https://transport.orgp.spb.ru/api/visary/operator/route` — поиск маршрута;
- `GET https://transport.orgp.spb.ru/api/visary/stop/byRoute?routeId=…` — направления,
  участки геометрии и остановки.

Это источники линий и остановок. Текущие позиции предоставляет отдельное
расширение `spb-live`, описанное ниже.
Построение поездки между двумя точками — отдельный провайдер маршрутизации,
описанный в [`ROUTING.md`](ROUTING.md). Ответы слоя ограничены 2 МиБ, запрос — 16 секундами;
небольшой кэш хранит до 4 ответов на 5 минут. При выключении запрос отменяется.

`spb-live` находится в `modules/live-transport.js` и запрашивает настоящие
позиции автобусов, трамваев и троллейбусов для видимой области от zoom 12
каждые 16 секунд после предыдущего ответа. В общем режиме действуют виды
транспорта и необязательный номер; выбранный набор задаёт точные типы, номера
и собственные цвета. Расширение использует отдельный запрос без пятиминутного
кэша линий, отменяет старую область, приостанавливается в фоне и проверяет
время позиции отдельно от времени получения. Контракт и проверенные
endpoints — в [`TRANSPORT-LIVE.md`](TRANSPORT-LIVE.md).

`spb-metro` находится в `modules/metro.js`: географические ветки, станции
от zoom 10 и отключаемые входы от zoom 15 читаются из локального снимка OSM.
Подтверждённого источника живых координат поездов метро нет. Подробнее —
[`TRANSPORT-METRO.md`](TRANSPORT-METRO.md).

В APK 0.6.1 доверие дополняется проверенными CA только для транспортного
домена. Причина — сервер присылает старый intermediate, тогда как сертификат
сайта подписан ключом intermediate 2024. Системные trust anchors и проверка
TLS сохраняются; изменения не устанавливают CA в настольную ОС или браузер.
Источники, fingerprints и воспроизводимая проверка — в
[`TRANSPORT-TLS.md`](TRANSPORT-TLS.md).

16 ноября 2026 года в Android WebView APK 0.6.1 модуль получил реальные
HTTPS-ответы без mocks: состояние `ready`, ошибка `null`, 89 объектов маршрута
и остановок. Это проверка конкретного запроса, а не гарантия доступности всех
маршрутов или будущей стабильности портала. Тесты с подставленными ответами
отдельно проверяют обработку данных и взаимодействие интерфейса.

`SloiBundledModules.searchProviders` экспортирует поиск автобусных маршрутов
для общего поля поиска. Провайдер доступен и при выключенном слое. Результат
содержит `moduleId`, название и patch настроек; выбор результата на стороне
приложения настраивает/включает модуль и показывает его границы. Это не
автоматическое включение от одного ввода текста.

Неотправленный черновик настроек не должен перезаписываться посторонним
`onChange` host. Спокойное состояние выключенного модуля не требует
дополнительной поясняющей строки; ошибки и предупреждения хранилища сохраняются.
Общий поиск маршрутов остаётся в основном поиске. Если после выбора результата
пользователь вручную двигает карту, поздняя активация транспорта не возвращает
камеру к его границам.

## Транспортные наборы и метро

`spb-live` оставляет три источника для автобусов, трамваев и троллейбусов,
даже когда пользователь выбрал несколько разноцветных маршрутов. Массив
набора передаётся строкой `settings.routes`; контракт примитивных настроек
host не расширяется. Хранилище наборов `sloi-transport-presets` версии 1
отделено от состояния модулей: до 20 наборов, по 1–20 маршрутов, название
до 48 символов и общий лимит 64 КиБ. Ошибка записи не меняет прежнюю коллекцию.
Подробнее — [`TRANSPORT-LIVE.md`](TRANSPORT-LIVE.md).

`spb-metro` использует три источника `lines`, `stations`, `entrances` и
встроенный проверяемый снимок OSM вместо сетевого списка станций.
`selectedLine: ""` показывает все шесть веток, `"1"`…`"6"` — одну;
`entrances` управляет входами. Выбор не требует сети, геолокации или
установки полного городского пакета. Источники, лицензия, дата и API каталога —
[`TRANSPORT-METRO.md`](TRANSPORT-METRO.md).

Проверки host подтверждают lifecycle, отмену, изоляцию ошибок и очистку
зарегистрированных ресурсов. Это не доказательство изоляции недоверенного кода
или измерение памяти и FPS на телефоне.
