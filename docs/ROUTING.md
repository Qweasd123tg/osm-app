# Построение пути

Экран «Маршрут» принимает начало и конец, предлагает режимы «Пешком»,
«Велосипед» и «Транспорт». Конец может быть взят из выбранного места карты.
Для начала по умолчанию используется геолокация, запрашиваемая при построении;
обе точки можно выбрать через поиск. Установленные адреса и места ищутся
локально; при отсутствии совпадений с сетью доступен Photon. Дата, цвет и параметры поставщиков
не выводятся пользователю отдельными настройками.

У обоих полей есть кнопка выбора на карте. Она временно скрывает редактор,
оставляет карту доступной для жестов и показывает прицел в центре полотна.
«Выбрать точку» переводит физический центр canvas в координаты через
`map.unproject`, учитывая сохранённый padding после `fitBounds`; простой
`map.getCenter()` здесь может указывать в другую точку. Photon и GPS не нужны;
точка сразу подписывается «Точка на карте». Если доступен `SloiPlaceNames.resolve`,
асинхронно подставляется ближайшее название/адрес; ошибка оставляет точку пригодной
для построения. Ответ меняет только подпись, никогда не переносит выбранные координаты.
Смена/редактирование точки и закрытие отменяют запрос; устаревшее имя не перезаписывает
новый выбор. Подтверждённые точки отмечены маркерами «А»/«Б», первый остаётся виден
при выборе второго. Для начала пути
такой выбор отключает использование геолокации. Он очищает прежний маршрут
только после подтверждения. Отмена, Escape и первое системное «Назад» возвращают
редактор с прежними полями, параметрами и линией; следующий Back закрывает редактор.
Ручное положение камеры при возврате сохраняется. Выбор другой страницы
закрывает незавершённый выбор точки.

После построения настоящие варианты сервиса показаны горизонтальными карточками:
время, расстояние, транспортные участки и пересадки. Карточки можно листать;
соседний вариант частично виден у края. Переключение карточки меняет линию и
описание без повторного запроса или перемещения камеры. Единственный ответ
сервиса остаётся одной карточкой; дополнительные варианты не выдумываются.
Иконки режимов и участков — единый SVG-набор с текстовыми подписями.
Пешие участки в краткой карточке показывают фактическое время; последовательные
пешие переходы объединяются только в сводке. Более трёх участков сокращаются
до трёх значков и счётчика `+N`. Полный список остаётся в закрытом по умолчанию
раскрытии «Поездка по шагам» под панелью выбора.

Раскрытия «Параметры» и «Поездка по шагам» анимируются через Web Animations
API за 190 мс в обе стороны. Повторное действие разворачивает текущий переход;
клавиатурное управление и введённые значения сохраняются, `prefers-reduced-motion`
отключает движение.

В режиме «Транспорт» раскрытие «Параметры» содержит «Без пересадок» и выбор
видов: автобус, метро, трамвай, троллейбус. По умолчанию разрешены все четыре;
можно оставить несколько или один. Пустой набор предлагает выбрать хотя бы один
вид до запроса геолокации/маршрута. Электрички и паромы не выдаются за поддерживаемые
режимы этого городского провайдера.
Выбор сохраняется при закрытии экрана и переключении режимов, но не применяется
к пешему или велосипедному пути. Изменение параметра отменяет текущий запрос
и удаляет результат с прежними условиями. Пешее расстояние, цена и параметры
поставщика отдельными неподдерживаемыми переключателями не выдаются.

Панель маршрута оставляет карту доступной для жестов. Если во время запроса
пользователь сдвинул карту, поздний результат рисует линию без автоматического
возврата камеры. Системная кнопка «Назад» закрывает панель маршрута.

Закрытие панели оставляет линию и компактную сводку; сводка открывает результат
снова, отдельное действие очищает маршрут. Выбор пути сохраняет выбранное
место и угол камеры. Остановки маршрута видны с zoom 15.

Пешие участки — синие пунктирные линии, велосипедные — зелёные. Для
общественного транспорта автобус обозначен янтарным, метро — фиолетовым,
трамвай — красным, троллейбус — бирюзовым. Геометрия, значки участков в
карточке и подробных шагах используют одну палитру; текстовые подписи и
пунктир отличают участки независимо от распознавания цвета. Цвет не является
отдельной пользовательской настройкой.

## Контракт провайдеров

`app/src/main/assets/modules/routing.js` отделяет сетевые источники от экрана:

```javascript
SloiRouting.registerProvider({
  id: "my-provider",
  modes: ["walk"],
  async plan({ from, to, mode, preferences, signal }) {
    // Возвращает массив нормализованных вариантов.
  },
});

const routes = await SloiRouting.plan({
  from: [30.3157, 59.9391],
  to: [30.3351, 59.9343],
  mode: "walk", // walk | bicycle | transit
  preferences: { directOnly: false, transportTypes: ["bus", "subway"] }, // только transit
  signal: controller.signal,
});
```

Координаты — `[longitude, latitude]`. Выбирается первый зарегистрированный
провайдер нужного режима. Встроенные ID — `osrm` и `spb-transit`.
Поддержка ограничения объявляется провайдером через `preferences: ["directOnly", "transportTypes"]`.
`transportTypes` принимает непустое подмножество `bus`, `tram`, `trolley`,
`subway`; отсутствие параметра означает все четыре. К другим режимам эти
параметры не применяются.
Запрошенное неподдерживаемое ограничение возвращает ошибку, а не игнорируется.
Это сменный реестр доверенных поставщиков из APK, пока не пакетный установщик
и не capability контекста `module-host.js`.

Каждый вариант содержит `provider`, `mode`, `distance` в метрах, `duration`
в секундах, GeoJSON `geometry`, список `legs` и ссылки `attribution`.
Участок содержит режим, подпись, геометрию, время, расстояние и остановки;
транспортный вариант дополнительно может содержать число пересадок.
Нулевой `sumFare` городского API не интерпретируется как бесплатный проезд:
стоимость приложение не показывает.

`routing-ui.js` создаёт экран отдельно от основного приложения:

```javascript
const routingUI = SloiRoutingUI.install({
  map,
  getDestination: () => selectedPlace,
  getCurrentPosition,
  searchPlaces: (query, { signal }) => search(query, signal),
});
routingUI.open();
```

Возвращаются `open`, `isOpen`, `isPicking`, `back`, `close`, `clear`, `dispose`
и `invalidateSearchData`. Последний отменяет старые подсказки и обновляет
видимое поле после смены сигнатуры установленных поисковых данных.
`back` отменяет выбор точки и возвращает редактор; `close` закрывает всё состояние
интерфейса маршрута для перехода в другой раздел. UI владеет своими источниками,
слоями и обработчиками; данные других расширений не заменяются. Отмена и
устаревшие ответы не должны показывать старую поездку поверх нового выбора.

## Пешком и велосипед

Используется публичный сервер OSRM организации FOSSGIS:

```text
https://routing.openstreetmap.de/routed-foot/route/v1/foot/{lon,lat;lon,lat}
https://routing.openstreetmap.de/routed-bike/route/v1/bike/{lon,lat;lon,lat}
```

Параметры: `overview=full&geometries=geojson&steps=true&alternatives=true`.
Данные — OpenStreetMap; профиль выбирается в URL. Официальные источники:
[описание и политика сервера](https://routing.openstreetmap.de/about.html),
[документация OSRM API](https://project-osrm.org/docs/v5.24.0/api/).

Публичный сервер допускает не более одного запроса в секунду, запрещает
массовое использование и требует корректный User-Agent, атрибуцию и ссылку
исправления карты. Клиент разносит старты запросов минимум на 1050 мс и
показывает ссылки OpenStreetMap, OSRM/FOSSGIS и «Исправить карту».
Перед ростом нагрузки нужен собственный или согласованный поставщик.

## Общественный транспорт Петербурга

Используется планировщик официального городского портала:

```text
GET https://transport.orgp.spb.ru/transit-api-otp/routes
    ?fromLat=59.8521&fromLon=30.3229
    &toLat=59.9343&toLon=30.3351
    &transports=bus,tram,trolley,subway
    &startTime=2026-11-17T10:00:00+03:00
```

Клиент отправляет текущее петербургское время через `Europe/Moscow`.
Это фактический контракт открытого клиента портала, а не опубликованный
стабильный API со SLA. Вызов `getBuildedRoutesFromTransitApi` найден в
[JavaScript официального портала](https://transport.orgp.spb.ru/_nuxt/33cdbf8.js);
назначение построения поездок подтверждает
[официальная инструкция](https://orgp.spb.ru/2023-522/). Контракт может меняться. 17 ноября 2026 года повторно прочитан тот же
официальный клиент: он передаёт выбранный список в `transports` и объявляет
типы `bus`, `tram`, `trolley`, `subway`. Приложение передаёт только выбранное
подмножество, не добавляя выдуманные параметры OTP.

Ответ `success:true` содержит варианты в `result`: общие `sumTime`,
`sumDistance`, `numTransfers` и участки `stages`. Путь участка преобразуется
из `{ longitude, latitude }` в MapLibre `[longitude, latitude]`; пешие переходы,
пересадки и транспорт сохраняются разными участками. `success:false` или
пустой список показываются как отсутствие поездок на текущее время.

Ответ дополнительно проверяется по выбранным видам до лимита пяти карточек:
вариант целиком исключается, если содержит запрещённый транспортный участок.
Участок никогда не вырезается из поездки, чтобы не получилась разорванная
геометрия. Переходы `walk`, `transfer`, `pathwaytransfer`, `subwaytransfer`
не считаются видом транспорта; `trolleybus`/`metro` нормализуются как
`trolley`/`subway`. Неизвестные будущие типы сохраняются при выборе всех видов,
но не пропускаются в ограниченную выборку. Если источник не вернул подходящую
поездку, приложение явно сообщает отсутствие вариантов с выбранными видами,
не подменяя их другим транспортом.

Городской wrapper не публикует параметр `maxTransfers` в фактическом контракте
своего JavaScript-клиента. Одноимённый параметр обычного OTP к этому URL не
добавляется: сервер мог бы его молча проигнорировать. «Без пересадок» строго
отбирает предоставленные городским сервисом поездки **до** ограничения числа
карточек. Число пересадок — максимум из объявленного `numTransfers` и числа
транспортных участков минус один. Два участка с одинаковым номером линии не
считаются автоматически одним транспортным средством: в ответе нет проверенного
признака interlining/stay-on-vehicle. Пешие и станционные переходы посадками не
считаются. Если подходящих вариантов нет, выводится «Среди вариантов сервиса
нет маршрута без пересадок»; маршрут с пересадкой взамен не показывается.
Это фильтр вариантов источника, а не доказательство отсутствия любого прямого
сообщения во всём городе.

Время прибытия показывается только при наличии корректных фактических
`startTime` и `endTime` поездки. Поля без UTC-offset трактуются в петербургском
времени городского API, независимо от часового пояса устройства. Для OSRM
время прибытия по текущим часам не подставляется.

Этот планировщик отличается от поиска автобусной линии по номеру:
`api/visary/operator/route` и `api/visary/stop/byRoute` обслуживают слой
`spb-bus`, а `transit-api-otp/routes` — поездку между A и B.
В Android остаётся доменное доверие проверенным CA портала;
проверка TLS не отключается. См. [`TRANSPORT-TLS.md`](TRANSPORT-TLS.md).

## Лимиты и проверка

Ответ ограничен 4 МиБ, путь — 80 000 координатами, показ — пятью вариантами.
Тайм-аут запроса — 20 секунд. `AbortSignal`, HTTP 429, пустой ответ,
повреждённая геометрия и отмена обрабатываются отдельно.
Маршруты требуют сети; городской пакет содержит локальные адреса/места
и здания, но не маршрутный граф. Выбор точки на карте работает без сети,
само построение пути — пока нет.

17 ноября 2026 года живые запросы к источникам были проверены на координатах
Петербурга: OSRM вернул пеший и велосипедный пути, городской планировщик —
поездку с метро и автобусные варианты с пересадками. Проверка источника не
доказывает весь интерфейс на телефоне и не гарантирует будущую доступность сервиса.

```bash
node tools/test_routing.mjs
python3 tools/test_routing_browser.py --chromium /usr/bin/google-chrome
python3 tools/test_map_picker_browser.py --chromium /usr/bin/google-chrome
python3 tools/test_disclosure_motion_browser.py --chromium /usr/bin/google-chrome
```

Браузерный сценарий использует настоящие UI и MapLibre, но подставленные
сетевые ответы и геолокацию. Он проверяет выбор точек, отмену, постоянную
высоту панели, сохранение камеры, транспортные участки и очистку маршрута.
Также проверяются выбранный `transports`, полная фильтрация поездок по видам,
пустой набор без GPS/сети, различные цвета геометрии/значков и сохранение выбора.
Подтверждённые «А»/«Б» остаются на карте, а поздние названия не меняют
координаты и не оживляют старый выбор после закрытия. Проверяются настоящие горизонтальные альтернативы и их выбор без новой
сети/сброса камеры, фактическое число пересадок, сохранение параметра, отмена
при смене условий, доступность карты и системная кнопка «Назад».
Отдельные сценарии проверяют прицел при ненулевом padding на ширинах
320/390/411 px, отсутствие поискового/GPS-запроса при выборе, возврат прежнего
маршрута после отмены и прерываемое раскрытие с клавиатуры/уменьшением движения.
Это отдельный уровень от живых HTTPS-запросов и проверки APK на устройстве.

В установленном APK 0.6.2 на Android 16 также выполнены живые запросы:
пешком — 1556 м / 1244.7 с, велосипед — 1824.6 м / 645.9 с. Из WebView
получен и нормализован дневной транспортный ответ для 10:00 Петербурга:
10056 м / 1686 с, пешие участки и линия метро 2. Запрос на текущее ночное
время вернул отсутствие поездки; приложение показало именно отсутствие
вариантов. Проверка не заменяет тест на физическом телефоне и не гарантирует
доступность публичных источников в другой сети.

Нативная проверка 0.6.6: после офлайн-выбора А/Б с адресами «Невский проспект 12» и «Невский проспект 10» и восстановления сети получен настоящий пеший маршрут OSRM. Его конечные точки совпали с координатами прицела; подстановка адресов не сдвинула выбранные точки.
