# Метро Петербурга: линии на карте

`modules/metro.js` регистрирует прежний модуль `spb-metro` с настройками
`{ entrances: true, selectedLine: "" }`. Пустая строка показывает все линии;
строки `"1"`…`"6"` — одну выбранную. Старое сохранённое значение `entrances`
совместимо. Выбор линии относится к просмотру карты, а не к поиску автобусов
или параметрам построения поездки.

В APK включён снимок `modules/metro-spb.json` размером 98 867 байт: шесть
географических трасс, 75 станций в порядке следования и 286 входов/выходов.
Он открывается без сети, разрешения геолокации и скачивания полного города.
Линии используют красный, синий, зелёный, оранжевый, фиолетовый и коричневый
цвет; цвет линии совпадает с цветом её станций и подписей. Подписи станций —
обычный текст (`pointLabelStyle: "text"`), точки небольшие. Входы появляются
только от масштаба 15; названия станций — от 12, точки — от 10. При отдалении
сначала исчезают подписи, затем точки; трассы остаются для обзора города.
На каждой активации используются три
источника host: `lines`, `stations`, `entrances`, с `colorProperty: "color"`.

## Данные и лицензия

Геометрия взята из действующих OSM relation `route=subway` в городском GeoPackage,
который уже поставлялся отдельным архивом `saint-petersburg-data-2026-11.zip`.
Это настоящие изгибы трасс, а не прямые отрезки между станциями. Из каждой пары
направлений выбран один путь; его компоненты `MultiLineString` сохранены без
искусственного соединения разрывов. Координаты округлены до семи знаков.

| Линия | Отображаемое название | OSM relation геометрии | Станций |
| --- | --- | --- | --- |
| 1 | Кировско-Выборгская | [252539](https://www.openstreetmap.org/relation/252539) | 19 |
| 2 | Московско-Петроградская | [252540](https://www.openstreetmap.org/relation/252540) | 18 |
| 3 | Невско-Василеостровская | [252536](https://www.openstreetmap.org/relation/252536) | 12 |
| 4 | Лахтинско-Правобережная | [252537](https://www.openstreetmap.org/relation/252537) | 9 |
| 5 | Фрунзенско-Приморская | [252541](https://www.openstreetmap.org/relation/252541) | 15 |
| 6 | Красносельско-Калининская | [20008262](https://www.openstreetmap.org/relation/20008262) | 2 |

В линии 4 присутствует «Горный институт», линия 6 — «Путиловская» и
«Юго-Западная». Строящаяся «Броневая» в список не включена. Состав и порядок
станций сверены 17 ноября 2026 с [официальным графиком метрополитена с
1 октября 2026](https://metro.spb.ru/rejimrabotystancii.html). В этом графике
«Фрунзенская» и «Парк Победы» закрыты на реконструкцию: они остаются в схеме,
отмечены `closed: true` и приглушены. Снимок не является оперативным источником
закрытий или расписаний; при обновлении данных эти пометки нужно сверять снова.

Позиции станций взяты из OSM station-node. Для закрытой «Фрунзенской», у которой
в этом снимке нет активного station-node, используется середина двух точек
платформ из OSM [stop_area 2618393](https://www.openstreetmap.org/relation/2618393).
Входы взяты из `railway=subway_entrance`. При наличии `colour` они отнесены к
соответствующей линии; у 12 входов без цвета линия определена по ближайшей
действующей станции. Поле `assignment` сохраняет этот способ (`osm-colour` /
`nearest-station`). Отдельный выход тоже обозначается точкой входа/выхода;
направления доступа и часы работы из этого снимка не гарантируются.

Муниципальный `/api/visary/stop/byLocationType` больше не нужен для открытия
метро. При сверке его ответа 17 ноября найдены повтор «Зенита», отсутствие
«Горного института» и координаты «Ломоносовской», совпадающие с «Пролетарской»;
поэтому этот список не используется как топология линий.

Данные © OpenStreetMap contributors, [ODbL 1.0](https://www.openstreetmap.org/copyright).
Снимок базы: `2026-11-15T06:38:16.727Z` (`gpkg_contents.last_change`), источник
[выгрузки BBBike](https://download.bbbike.org/osm/bbbike/SanktPetersburg/).
SHA-256 исходного упакованного городского архива:
`fd9a7a34a26de235b548df06fc6fb3bdcbc8b00cb3e65d4267bc6c75377da81d`.
Архив был переупакован проектом, это не заявленный официальный checksum BBBike.
SHA-256 `metro-spb.json`:
`cf14951be3e9f9c6cc466e2be4eab6c01cd105bcfed89b62b0e6d1cc8b0e1c1c`.

При воспроизведении снимка: читать GeoPackage в режиме `mode=ro`, извлечь
`multilinestrings.geom` по перечисленным OSM relation ID, station-node из
`points` по `station=subway` с цветом линии, исключить строящиеся станции,
добавить две закрытые станции и упорядочить по официальному графику. Входы
берутся из `points` с `railway=subway_entrance`; исходная база не изменяется.

## API для рабочего экрана

`SloiMetro.lines` — замороженный массив метаданных `{ id, name, color }`,
доступный сразу после загрузки скрипта. Идентификаторы — строки.

`await SloiMetro.catalog({ signal })` возвращает замороженный объект:

```js
{
  sourceUpdatedAt, checkedAt, attribution, license, licenseUrl,
  lines: [{ id, name, color, bounds, stations: [
    { id, name, coordinates: [longitude, latitude], closed, note }
  ] }]
}
```

В публичном каталоге нет тяжёлой геометрии трасс. `bounds` —
`[[west, south], [east, north]]`, подходящие для `fitBounds`. Каталог можно
использовать для цветных кнопок линий и списка станций; выбор станции передаёт
её фактическую позицию камере. Модуль сам камеру не перемещает.

Локальный JSON загружается один раз, разбирается и проверяется до передачи
host. Ограничения: 256 КиБ потоковых данных, восемь секунд, ровно шесть линий,
не более 32 станций на линию, 600 входов и 10 000 координат трасс, координаты в
пределах региона. Ошибка не кэшируется. Одновременные клиенты разделяют чтение;
отмена одного не мешает остальным, отмена последнего прерывает чтение. Отменённая
активация не записывает слои. Переключение линии использует неизменяемый кэш,
не запускает сетевые запросы или таймеры опроса.

Проверка `node tools/test_metro.mjs`: фактический снимок и продолжения линий,
раздельные позиции «Ломоносовской»/«Пролетарской», отсутствие дубля «Зенита»,
75 станций, шесть цветов, выбор линии/входов, локальный кэш, независимая отмена,
отсутствие поздних записей, повтор после ошибки, лимиты и проверка схемы.
Это проверка данных/логики; визуальная и Android-проверка относится к интеграции
основного приложения.
